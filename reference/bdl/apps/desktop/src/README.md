# Frontend ownership

- `desktop/app/`, `desktop/pages/`, `desktop/components/`: desktop shell, page templates and desktop-specific controls. Page CSS stays beside its page.
- `mobile/app/`, `mobile/pages/`, `mobile/components/`, `mobile/styles/`: mobile shell, page templates, touch controls and mobile styling. Phone and future tablet layouts share this platform family.
- `app/AppWorkspace.vue`: selects the platform's lazy page map; only one version mounts.
- `shared/features/`: common page state, lifecycle, selection, actions and reusable feature forms. Each feature owns its composables, tests and any shared form styling. Call composables once from the mounted page's setup, not at module scope.
- `shared/stores/`, `shared/api/`, `shared/utils/`: common application data, commands, contracts and pure helpers.
- `shared/ui/`, `shared/styles/`: platform-neutral controls, theme tokens and global styles.
- `shared/platform/environment.ts`: system identity; use platform capabilities for system operations, and available window width for responsive presentation.

Mobile and desktop pages can evolve independently. Do not add platform branches to the page templates. Reuse small controls, settings sections, dialogs and task widgets where their interaction is the same. Shared settings field styles live in `shared/features/settings/SettingsForm.css`; each page owns its surrounding layout.

Dependency direction is `app -> desktop/mobile -> shared`. Shared modules never import either platform's views, and desktop/mobile never import each other's views. ESLint rejects static imports that cross these boundaries. Do not add compatibility re-export files in the old folders; update consumers to the owning module. Tests stay beside the source they verify.

`apps/desktop` remains one frontend and Tauri project for desktop and Android builds. Keep stores, API contracts and task submission common rather than copying them into platform folders. Responsive changes within the mobile family must preserve page state; a wide Android window must not acquire desktop-native window controls or filesystem assumptions.

Template refs used by the page composables retain the `download-planner` ref name in both templates. Library detail passes reactive props into its composable so changing folders cannot retain an old source. Both pagination layouts use `shared/ui/usePagination.ts`.

Cover images use `shared/utils/coverUrl.ts` to normalize HTTP and protocol-relative URLs. Set `referrerpolicy="no-referrer"` **before** `src` on the image: Vue's initial DOM mount can start the request as soon as it assigns `src`. The mobile library browser test verifies the actual request has no Referer header, not just that the attribute exists.

## Mobile interaction patterns

Shared `Dialog.vue` uses UModal's `scrollable` mode to center content inside the overlay without CSS translate. The component owns safe-area padding and viewport height limits, with `vh` as a fallback and `dvh` when supported. Keep the header/footer from shrinking; scroll long content inside the body, or let fixed-height feature forms own their inner scroller. Do not restore fixed 50% positioning or an unconditional 640px height. These constraints apply to both platform families. `MobileSheet` selects a phone bottom sheet or a compact centered `TabletActionDialog` using the mobile shell's readonly layout state; callers retain form state across layout changes.

Mobile pages do not import desktop SourceParseControls, Tabs, or TransferTaskTable. MobileTabs renders counts as plain, nonshrinking text, without badge primitives. Library detail hides the category tabs; the heading contains title and load status only. MobileSourceMenu puts batch size and collection-wide operations in MobileSheet. Continue-loading stays at the end of the scrollable media list. MobileTransferList owns touch task rows and their action sheet, using the shared task view model and virtual-window utility. Settings uses category cards and a back action rather than desktop section tabs. In phone layouts, MobileSheet enables UModal fullscreen mode and constrains the content into a bottom sheet; do not reintroduce centered modal translate utilities and try to cancel them with `translate: none`, because the production CSS transform can preserve Nuxt UI's `-50%` translation.

`MobileListHeader` combines category tabs and `MobileListActions` in one row. Phone transfer counts stack below labels; rail counts remain inline. The parse home form is centered and limited to 75% width in rail layouts, and nearly full width on phones: paste/scope controls, input, then submit. Settings sections share `SettingsCard` for functional groups, with rail parameter grids and single-column phone layouts. Preset editing uses a natural-height Dialog, an auto-fit name/template grid and three stretched workflow tabs; retain spacing between the header, fields, tabs and body. Shared Tabs owns selected weight/underline and restricts hover to inactive triggers so Android touch hover cannot override selection.

The mobile library collection index uses a padded `MobileListCard` group with inset rows and a gap between columns. Each row has exactly two text rows: one title, then owner + video count. Covers use the mobile density tokens (phone 72×48, rail 96×54 before root scaling) and a 4px radius. Collection descriptions stay out of this index; use the detail view for deeper context. Rows remain transparent within the shared light/dark card background, separated by dividers.

Keep scroll ownership explicit: page → flex panel → min-height:0 list; pagination and the download footer cannot shrink. Verify with more rows than fit on screen. The mobile layout tests include 356-item collection metadata, 243 transfer records to exercise virtualization, 320px width, populated action sheets, light/dark themes, and batch selection. Browser fixtures must return queue_logs and settings_update responses when tasks or theme changes are included.

Mobile styles, shared controls/features and theme sizes use rem with the original 16px-root dimensions preserved. Responsive queries retain px. In Android rail windows at DPR >= 1.5, AppMobile sets `bdl-mobile-density-scaled` on html and the mobile stylesheet sets its root font size to 60%; portrait phones, ordinary-density windows and desktop keep the default. This controls the size of pages and portaled UI together. Use normal viewport units and keep system safe-area values unscaled. Do not replace this with CSS zoom/transform: the attempted root zoom caused select popup width and position errors. Check rendered proportions and operate floating menus after changing density.

The mobile navigation has four destinations: parse, library, transfer, and personal (internally the existing settings tab). In narrow portrait windows the mobile shell uses a 48px logo + BDL header and bottom navigation. At 768px width, or in landscape windows at least 480px wide and at most 500px high, it uses a left navigation rail and gives the workspace the full available height. Rail media rows use 96×54 covers and a 64px row before root density scaling; short landscape activates `mobile-layout-compact` with a 56px rail and smaller typography/toolbars. Other windows retain 72×48 covers and 62px rows. Density must address the whole content/control proportion; moving navigation alone is insufficient. `AppMobile` owns both media queries, root classes, safe-area padding and grid areas; `AppWorkspace` occupies the named workspace area. Keep queries in legacy-syntax `matchMedia` strings because production CSS minification rewrites CSS queries to range syntax. Resize changes presentation without changing platform identity or remounting pages.

Main pages start with content or compact action controls, while settings/detail pages own their small back toolbar. `PersonalPage` owns the home/settings/about stack via `ui.mobilePersonalPage`; keep its single element root for the workspace transition/KeepAlive. Parse, library and transfer lists use `MobileListCard` for the rounded, padded, scrollable group; short lists shrink to content, and download/management footers remain at the bottom. Row padding is separate from card padding so checkboxes and artwork also have room inside the selected background. `MobileListActions` owns the shared search/options/manage buttons with transfer-sized icons; `MobileListSearch` owns the inline search field. `useMobileListSelection` supplies enter/exit behavior: default browsing hides checkboxes, managing reveals them, and finishing clears selection. Clicking a parse/detail video enters management and toggles its selection; transfer keeps inspect/play and long-press entry. Full-source/current-page selection stays in the management footer; filtering changes visible rows, not selected IDs or selection scope. Transfer virtual-window calculations measure actual row height, subtract card padding from the visible viewport/offset, remeasure after asynchronous arrival, and observe scroller resize. Keep exactly two text rows (title + status/meta), put the primary play/pause/retry action on the artwork, and do not restore visible right-side action buttons. In compact transfer rows, completion and duration move into metadata; regular rows retain artwork badges. Active status names the current resource stage (`下载视频中`, `下载音频中`, optional assets, then `合并中`), and the mobile percentage belongs to that current resource rather than the aggregate whose denominator changes between tracks. Check at least eight completed rows at 320×844 and seven parse rows at 568×356 / DPR 2.25 (six with tested asymmetric insets), with readable covers and checkboxes below one third of row height. Keep scrollers free of horizontal overflow. Mobile card tokens are scoped to `.platform-mobile`, including their dark theme. `MediaArtwork` is shared by media rows and task cards; planner tasks persist cover/duration in their refresh intent and fall back to parsed CID metadata or downloaded cover resources.

The Android host source is `../src-tauri/android/MainActivity.kt`; the Tauri wrapper syncs it into ignored `gen/android` before Android commands. Edit the owned source, not generated Wry/Tauri classes. Its WebView creation hook lowers Android's default 8 CSS px font floors to 1 so frontend density/font sizes render correctly; system text zoom is retained. Browser previews cannot verify this native setting, so check an actual WebView screenshot when changing tablet typography.

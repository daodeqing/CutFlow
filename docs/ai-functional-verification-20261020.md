# AI 功能检查记录（2026-10-20）

本次检查以 Windows 实机为准。检查时安装的是 CutFlow 0.6.5、GFlow 0.1.19；修订版本为 CutFlow 0.6.6、GFlow 0.1.20。下文区分真实服务结果与本地模拟验证，发布版本、云端构建编号及下载校验由最终交付记录补充。

## 实机结果

| 检查项 | 结果与边界 |
| --- | --- |
| 连接与模型目录 | 可以读取当前服务的模型和能力。目录可访问不代表图片生成一定成功。 |
| 真实 Flow 项目 | 成功建立真实项目并绑定账号。创建项目成功不代表已通过生成验证。 |
| 旧作品恢复 | 仅重试下载，成功恢复已有的 1536 × 2752 原图；没有重新提交生成。 |
| 一次真实新图 | 进度到 34% 后失败；服务记录耗时约 109.1 秒，错误为 Failed to obtain reCAPTCHA token，没有返回新作品。 |
| 连续改图 | 尚未通过真实服务验收。 |
| 视频 | 仅做本地协议、媒体保存及模拟测试，未执行真实视频生成。 |

因此，目前不能将这套 AI 功能标为“实机全部可用”。本次真实失败发生在服务获取 reCAPTCHA 令牌阶段；现有证据不能直接推断为账号失效、模型不可用或前端连接错误。界面保留原任务及具体错误，不自动更换账号、项目、模型或重复提交。

只读检查最近 6 小时 Windows Application 日志，未发现 Chrome 对应的 Application Error、Application Hang 或 Windows Error Reporting 事件。这个结果只能说明这些日志中没有对应记录，不能排除浏览器内部页面失败、未记入日志的异常或上游验证限制。

## 本次修复

- 防止迟到且没有版本号的提交回执，把已收到的生成或完成状态覆盖回“等待中”。
- 首次活动任务快照遗漏刚结束任务时，单独核查已知活动任务，避免界面永久停在旧状态。
- 下载重试按会话防止重复点击；迟到回执不能覆盖新的完成结果。下载阶段显示“下载中”“停止下载”，明确不会重新生成。
- AI 页的“连接设置”直接打开 AI 服务设置；项目标签改为“已绑定 Flow”，不把持久绑定说成实时可生成。
- 新建项目弹窗不再把未确认的能力快照描述为“正在检查”或直接要求升级插件。创建时仍由后端核查，返回后同步轻量目录状态。
- 视频参考图上限按模型和时长核查，并由前后端同时校验。当前 Quality 8 秒分支不支持参考图，明确阻止提交并保留草稿；Lite/Fast 4、6 秒最多 2 张，8 秒最多 3 张。视频不再显示“连续改图”入口。
- 当前项目的模型目录具有约束力；已移除模型、空目录、错误类别或不支持参数应在提交前明确报错。
- 对齐标准图片和视频 data URI 的接收、传输和保存限制；视频保存支持 MP4、WebM、MOV 并检查容器，避免已有视频无法落盘。
- 完整媒体返回后在结束标记前断流时，保持结果待核查并保存可验证的下载凭据，支持仅重试下载，不自动重新生成。
- 插件保留浏览器启动、页面加载及连接异常的安全分类，不记录凭据或完整异常，不改变验证及重试策略。
- SSE 分隔符扫描和大段媒体提取改为线性处理，避免随着大结果增长反复扫描。媒体读取设置上限，并去掉生成回执中的重复媒体字段，减少不必要的内存及磁盘占用。

画质选项依然以当前账号、模型及服务实际返回的能力为准。4K 可以展示但仅在能力明确开放时启用；本次没有通过真实 4K 生成验收。

- CutFlow 工作台完整本地测试：67 项通过（8 项单元、38 项协议、21 项项目测试）。

本地测试证明相关状态和协议分支在受控输入下符合预期；不会替代真实账号的新图、连续改图、4K 或视频验收。后续真实请求必须继续遵守用户授权的调用数量，不能为了测试反复生成。

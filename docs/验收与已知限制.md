## 明确限制

- 这是 Concat + BDL CLI 的 P0 集成，不是已经完成 bdl-core 常驻服务提取的 MVP。
- 仅提供普通视频 / 多 P 的入口；没有收藏夹、UP 主空间、番剧、课程或附件下载界面。
- 没有二维码登录；凭据设置只支持 Windows DPAPI。其他系统拒绝以明文降级保存。
- 下载进度仅展示状态，没有实时百分比、速率或预计剩余时间。
- 暂停会结束下载进程树，完成文件及检查点保留；未完成单文件是否按字节继续，取决于 BDL。
- 画质严格模式采用 UHD 像素门槛；超宽 3840×1600 会拒绝，不以“4K”名称放行。
- ffprobe 验证媒体结构与轨道，不代表逐帧解码无损坏。复杂格式仍需编辑器真实预览及导出验收。
- 入库幂等当前依靠规范化绝对路径与文件大小；尚未实现完整内容哈希、跨路径去重或跨电脑自动迁移。
- 素材母版保存在 `%LOCALAPPDATA%\CutFlow\jobs`；不要将该目录作为可再生缓存清理。
- 源码中保留原编辑器的工程和偏好格式，部分界面与关于页面仍包含上游名字和版权说明。
- 安装脚本不会清理用户媒体，不提供自动更新，也没有代码签名证书。

## Windows 最短实机验收步骤

1. 先运行 `scripts/Build-Windows.ps1 -Installer`，要求全部构建与启动检查成功。
2. 无账号情况下导入本地短视频，分割成两段，导出并播放，保存工程并重启。
3. 用自己允许保存的真实 4K 视频验证严格模式；再用没有 4K 的视频验证拒绝降档。
4. 下载中暂停、关闭、重开、手动继续，确认未生成虚假“已完成”任务。
5. 下载时从工程 A 切到工程 B，确认素材不会进入 B；打开 A 后执行入库。
6. 工程保存后重放完成事件，素材只出现一次；移动媒体时明确提示重定位。
7. 最终导出探测为要求的 3840×2160、帧率与音轨，并人工核对切点和音画同步。

任何一项阻断失败，都应先修复并更新此文件，不能仅凭“源码已生成”标记正式版完成。

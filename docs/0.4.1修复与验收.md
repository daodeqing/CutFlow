# CutFlow 0.4.1 修复与验收

日期：2026-10-16。便携版启动入口为 CutFlow.exe。应用为独立 Windows 程序，运行不依赖本次开发会话。

## 已修复

- 启动使用须知改为 daodeqing、CutFlow 仓库与作者 GitHub 主页，保留第三方许可证说明。
- 连接检查区分“已读到模型列表”和“已验证实际回复”，新增小用量回复测试。
- GPT Image 使用 /v1/images/generations，有参考图时使用 /v1/images/edits；GFlow 等使用 Chat Completions。
- 图片支持 1–4 张，逐张保存；比例与画质按模型显示，GPT Image 显示低/中/高与支持的比例，GFlow 显示 1K/2K/4K。成品实际尺寸会显示在结果下方。
- 视频支持比例、4/6/8 秒，Omni 额外提供 10 秒。参数会传到服务端，是否支持取决于模型。
- 模型改为页面内搜索与滚动列表；定时刷新任务不会关闭列表，文本模型不再混进已识别的媒体模型。
- 新增显眼的“停止生成”，HTTP 尚未返回数据也可取消；多图停止后不再提交后续图片，已保存结果保留。
- B站下载弹窗新增本次画质与不可用策略，默认最高可用；修复预设覆盖本次画质，保证任务和输出流程都使用本次选择。账号和原视频决定真实上限，不进行画质放大。
- GFlow 改为后台专用浏览器，限制验证码超时，停止自动重发，任务结束回收浏览器；修复 Flow Cookie 作用域遗漏和 Windows 本地化输出解码错误，移除 PowerShell 浏览器进程扫描。当前任务取消使用请求专属 Windows 命名管道和短期能力令牌；取消测试耗时约 0.25 秒，并确认控制文件和专用浏览器均已回收。

## 实测结果与边界

普通文本模型 gpt-6-luna 返回 HTTP 200 和 OK。真实 GPT Image 请求成功两次；其中一次通过新版 CutFlow 完整任务流程保存 PNG，1254×1254，989164 字节。一次直接接口请求的返回尺寸与请求不一致，说明还存在上游参数行为差异，界面以实际成品信息为准。

前端 269 项、工作台 27 项、下载后端 129 项通过，下载后端保留 6 项上游条件跳过。最终主程序的模拟集成验证了图片/视频、4 张独立结果、参考图、重启幂等、断流、额度不足和只重试下载。

GFlow 当前账号的验证码前置步骤仍未通过，不能标记为 GFlow 生图成功；真实视频未提交验收。B站画质选择与任务参数已通过本地回归，未执行真实账号 8K/4K 下载。不要把“模型可见”理解为所有模型都已成功生成。

本机诊断、账号与清理明细保留在本地，不随源码上传。原有用户账号、密钥、历史任务与素材不随程序更新被替换。

## 详细检查补充

- 下载重试按钮由后台检查实际结果回执和未保存素材后提供。验证码失败、尚无结果地址、或多图仅后续生成失败且前面已保存的任务不再显示无效下载重试。
- 下载重试和最终成功会清除旧错误，避免已完成任务仍显示上一次失败原因。
- 修正云端产物名称为 0.4.1；Windows 工作流分别编译主窗口和编辑器，再做双窗口与模拟服务集成验收、便携版和安装包打包。
- GFlow 前置诊断捕获 Google CookieMismatch；修正旧版复制 Cookie 到多个站点的处理后，该次复查进入 Flow /projects，但页面加载仍未就绪。没有据此宣称验证码或 GFlow 图片生成成功。本次排查没有新增付费生成请求。
